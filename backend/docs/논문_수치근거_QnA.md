## 2. 예상 질문과 답변

### Q1. 손실인데 왜 지연처럼 보이나요?
TCP는 손실된 패킷을 재전송 타이머(RTO)가 지난 뒤 다시 보냅니다. 응답이 실패하지 않고 늦게 도착하므로, 응용 계층에서는 타임아웃이 아니라 지연으로 기록됩니다.
- **근거:** 60초 측정에서 버스트 손실 조건의 타임아웃은 415건 중 2건뿐이었고, 200ms 이상 지연 응답이 37건이었습니다(`retrans_summary.csv`). 같은 구간의 TCP 재전송 비율은 5.67%로 정상(0.12%)의 약 46배였습니다(`raw_dataset_20261004/README.md`).

### Q2. 왜 200ms가 기준인가요?
Linux TCP의 최소 RTO가 200ms이기 때문입니다[4]. 손실 후 재전송된 응답은 최소 200ms만큼 늦어집니다.
- **근거:** 60초 측정에서 늦은 응답 37건 중 26건이 200ms 바로 위에 몰려 있습니다(`retrans_summary.csv`의 `near_200ms`).

### Q3. 계산한 RTO가 실제 커널의 RTO와 같은가요?
같지 않습니다. 응용 계층에서 측정한 RTT로 RFC 6298 방식, 즉 max(200ms, SRTT + 4·RTTVAR)를 따라 **추정**한 값입니다. 커널 값을 읽지 않는 것이 이 방법의 장점입니다. 대신 이 추정이 맞는지를 실제 재전송 기록으로 따로 검증했습니다.
- **근거:** 검증 세션에서 RTO 초과 응답의 94%가 실제 재전송이었고, 버스트 손실 조건에서는 100%였습니다(`verify_rto_vs_retrans.csv`).

### Q4. "실제 재전송"은 어떻게 측정했나요? 믿을 수 있나요?
수집기를 `PA_LOG_RETRANS=1`로 실행하면, 요청 직전과 응답 직후에 `/proc/net/snmp`의 TCP 재전송 카운터(RetransSegs)를 읽어 그 차이를 요청마다 기록합니다(`retrans_segs` 열).
- **한계:** 컴퓨터 전체의 카운터이므로 다른 통신의 재전송이 섞일 수 있습니다. 수집 중에는 다른 네트워크 작업을 하지 않았습니다(`raw_dataset_20261009/README.md`).
- 정상 조건 RTO 초과 13건이 모두 실제 재전송과 일치한 것도 이 기록이 맞다는 근거가 됩니다.

### Q5. GE 설정값(p=5%, r=50%, 90%)과 지연 120ms는 왜 그 값인가요?
**값을 정한 이유는 기록되어 있지 않습니다.** 사실대로 답하고, 관측된 결과와 일반화 실험으로 보완합니다.
- **기록된 의도:** 스크립트 문구에 B는 "CCTV 혼잡", C는 "EMI 오염", D는 "DoS 공격"을 흉내 낸 것으로 적혀 있습니다(`master_collector.sh`).
- **관측된 결과:** 이 설정에서 지연 장애는 실측 약 290ms로 1초 타임아웃 안에서 지연으로 기록되었습니다(B 타임아웃 0건). 버스트 손실 장애는 연결이 끊기지 않고 대부분 재전송으로 복구되었습니다(60초 중 타임아웃 2건).
- **값에 묶이지 않았다는 근거:** 일반화 세션에서 다른 강도(B 60·200ms, C p 2·10%)로도 시험했습니다(`generalization_collector.sh`).
- GE 모델을 쓴 이유는 손실이 연속해서 몰리는 버스트 손실을 재현하기 위해서입니다[3].

### Q6. 버스트 손실(C)만 기본 지연이 2ms인데, 그 차이로 맞힌 것 아닌가요?
일부 영향이 있을 수 있다는 점을 인정하고, 핵심 특징의 효과를 따로 보여 줍니다.
- 60초 측정의 RTT 중간값은 정상 3.37ms, 버스트 손실 5.19ms로 차이가 있습니다(`retrans_summary.csv`).
- **RTO 초과 비율 하나만 추가해도** 버스트 손실 재현율이 0.51에서 0.85로 올랐습니다. 평균 RTT 계열(SRTT, RTTVAR)만 추가한 경우는 0.86입니다(⚠️ 근거 파일 미등록).
- RTO 초과 판정의 정확도(94%, 버스트 손실 100%)는 기본 지연과 관계없이 요청 단위로 확인한 결과입니다.
- 논문 결론에 이 한계를 적었고, 후속 연구로 기본 지연을 맞춘 재수집을 제시했습니다.

### Q7. 8.7%와 8.2%가 같다는 뜻인가요?
아닙니다. 8.2%는 **패킷 하나** 기준의 설정 손실률이고, 8.7%는 **요청 하나** 기준으로 손실로 판별된 비율입니다. 요청 하나에는 요청, 응답, ACK 등 여러 세그먼트(약 6.5개)가 오가므로 단위가 다릅니다. 그래서 논문에는 "비슷한 수준"이라고만 썼습니다.

### Q8. RTO 방식이 모든 손실을 찾나요?
아닙니다. 버스트 손실 조건에서 실제 재전송이 있었던 요청 371건 중 RTO 초과로 잡은 것은 159건(약 43%)입니다(`verify_rto_vs_retrans.csv`의 C 행 `recall`). 나머지는 RTO보다 빠른 복구(빠른 재전송 등)로 응답이 수십 ms 정도만 늦어진 경우로 추정됩니다. 대신 **잡은 것은 모두 실제 재전송**이었습니다(정밀도 100%). 모델은 RTO 초과 비율과 함께 SRTT, RTTVAR도 사용하므로 최종 버스트 손실 재현율은 0.93입니다.

### Q9. 지연 조건에서 RTO 초과의 일치율이 60%인 이유는?
지연 장애는 지연이 ±40ms로 크게 흔들려서, 재전송 없이도 RTT가 갑자기 커져 RTO를 넘는 경우가 있습니다(30건 중 12건). 버스트 손실 판별에 쓰는 조건(C)에서는 100% 일치합니다(`verify_rto_vs_retrans.csv`의 B, C 행).

### Q10. 일반화 성능이 낮은데 실제로 쓸 수 있나요?
학습하지 않은 강도에서는 Macro F1이 0.549였습니다. 다른 강도의 데이터를 학습에 추가하자 0.743으로 올랐고, 지연 재현율은 0.29에서 0.98로 올랐습니다(`more_training.csv`).
- **정확한 의미:** "여러 강도를 학습시키면 그 강도들을 잘 판별한다"는 것입니다. 시험 데이터는 학습에 쓰지 않았지만, 시험 데이터와 같은 강도가 학습에 들어갔으므로 **처음 보는 강도에 대한 일반화를 증명한 것은 아닙니다.**
- 실제 현장 적용을 위해서는 더 다양한 강도의 데이터와 실제 산업망 검증이 필요하다고 결론에 적었습니다.

### Q11. 복합 장애(D) 성능이 낮은 이유는?
D 시나리오는 시작 5초가 정상 상태인데, 이 구간도 D로 라벨링되어 D 데이터의 약 70%를 차지합니다. 이 구간의 RTT 중간값(15.6ms)은 정상 A(15.95ms)와 거의 같아 구별할 수 없습니다. 첫 5초를 빼고 평가하면 D 재현율이 0.28에서 0.73으로 오릅니다(`results_20261004/d_first5s.csv`). 라벨 구간 재설계를 후속 과제로 적었습니다.

### Q12. 왜 일반 교차검증이 아니라 시간 블록 교차검증인가요?
연속으로 측정한 샘플은 서로 비슷합니다. 무작위로 나누면 바로 옆 시점의 샘플이 학습과 시험에 동시에 들어가 성능이 부풀려집니다. 그래서 각 시나리오 데이터를 시간 순서대로 5개 블록으로 나누고, 블록 단위로 학습과 시험을 나눴습니다(`eval_tcp_features.py`의 `block` 열).

### Q13. 모델 설정은?
Random Forest, 트리 100개, 최대 깊이 10, 클래스 불균형 보정(`class_weight="balanced"`), 난수 시드 42로 설정했습니다(`eval_tcp_features.py`의 `rf()`). 시드를 고정했기 때문에 다시 실행해도 결과가 같습니다.

### Q14. 60초 측정은 왜 60초인가요?
nstat은 시작과 끝 사이의 컴퓨터 전체 재전송 합계만 셉니다. 장애가 30초마다 바뀌는 수집 루프에서는 여러 장애가 섞이므로 한 조건만 고정해서 측정했습니다. 60초는 비율을 비교하기에 충분한 요청 수(415~574건)와 재전송 수(154건)가 나오는 실용적인 길이입니다. 이 측정은 원인을 확인하기 위한 예비 확인이고, 정확도는 요청별로 재전송을 기록한 검증 세션으로 확인했습니다.

### Q15. lo(루프백)에서 실험한 결과를 실제 망에 적용할 수 있나요?
lo에서는 지연이 요청과 응답에 각각 적용되어 실측 RTT가 설정의 2배 이상이 됩니다(120ms → 약 290ms). 그래서 netem 설정값이 아니라 매 요청의 실측 RTT를 판별에 사용했습니다. 실제 산업망 검증은 후속 연구로 남겼습니다.
