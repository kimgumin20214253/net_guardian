# AI 추천 대응가이드 — 11가지 세부 사례와 근거 정리본

이 문서는 `backend/fault_tiers.py`에 구현된 "AI가 지연/유실/복합 장애 중 하나의 세부 사례를
추천해주는 기능"이 어떤 근거로 만들어졌는지 정리한 것이다. 숫자/임계값은 이 프로젝트 자체 데이터
분석 결과이고, 조치 문구의 근거 표준은 원문 PDF를 직접 읽고 대조한 것만 "확인됨"으로 표시했다.

---

## 1. 전체 구조 — 11가지 세부 사례

| 장애 유형 | 사례 ID | 이름 | 구분 기준 |
|---|---|---|---|
| 지연(B) | `b1` | 순수 지연 | 최근 15건 중 RTO 초과 0건 |
| 지연(B) | `b2` | 재전송 신호 혼재 | 최근 15건 중 RTO 초과 1건 이상 |
| 유실(C) | `c0` | 0단계(재전송 신호 없음) | RTO 초과 0건 |
| 유실(C) | `c1` | 1단계(경미) | RTO 초과 1건 |
| 유실(C) | `c2` | 2단계(중간) | RTO 초과 2건 |
| 유실(C) | `c3` | 3단계(심함) | RTO 초과 3건 |
| 유실(C) | `c4` | 4단계(매우 심함) | RTO 초과 4건 이상 |
| 복합(D) | `d1` | 전환 초기(분석 중) | 장애 전환 후 5초 미만 |
| 복합(D) | `d2_low` | 손실 비중 낮음 | 5초 이후, 손실률 30% 미만 |
| 복합(D) | `d2_mid` | 손실 비중 중간 | 5초 이후, 손실률 30~60% |
| 복합(D) | `d2_high` | 손실 비중 높음 | 5초 이후, 손실률 60% 이상 |

"RTO 초과"는 TCP 재전송 기준시간(RFC 6298, `RTO = max(200ms, SRTT + 4×RTTVAR)`)을 넘겨 응답이
온 경우를 뜻한다 — 논문이 유실 판별 성능을 0.51→0.93으로 끌어올린 바로 그 방식이며, 이 프로젝트에서는
지연(B)에도 같은 방식을 적용해 재전송 신호 혼재 여부를 추가로 구분했다.

PDF 페이지 번호와 다르다), "PDF 페이지"는 PDF 뷰어에서 실제로 이동해야 하는 페이지 번호다.

### 원문에서 직접 확인한 핵심 문장 (파일·페이지·위치 포함)

| 문장 | 파일 위치 |
|---|---|
| *"OT systems are generally time-critical, with the criterion for acceptable levels of delay and jitter dictated by the individual installation."* | **PDF 46페이지**(인쇄쪽수 29), 2장 소제목 "Comparing OT and IT System Security" 중 "Timeliness and performance requirements" 항목 |
| *"Any security measure that impairs safety is unacceptable."* | **PDF 46페이지**(인쇄쪽수 29), 같은 소제목 중 "Risk management requirements" 항목 |
| *"Some OT employ redundant components – often running in parallel – to provide continuity when primary components are unavailable."* | **PDF 46페이지**(인쇄쪽수 29), 같은 소제목 중 "Availability requirements" 항목 |
| *"Ensuring that critical components are redundant and are on redundant networks"* | **PDF 21페이지**(인쇄쪽수 4), Executive Summary의 defense-in-depth 전략 글머리목록 |
| *"Cyber-related events, such as the loss of network communications, could trigger these fail-safe events... organizations should define the thresholds at which OT components can operate with reduced or disrupted capabilities."* | **PDF 96페이지**(인쇄쪽수 79), §5.3.1 "Cyber-Related Safety Considerations" |
| *"OT network owners should exercise extreme caution when permitting active scanning on an operational network..."* (참고용, 체크리스트 명령어가 장애 중인 라인을 공격적으로 스캔하면 안 된다는 근거) | **PDF 226페이지**(인쇄쪽수 209), 부록 §E.2.3 "Active Scanning" |

## 5. 아직 남은 것 (미검증)

- `c1`~`c4`의 "차폐 케이블/접지/EMI" 물리계층 조치는 여전히 2차 자료 수준(KS C IEC 60364-4-44라는 표준 번호만 확인, 원문 미열람).
- IEC 62443 관련 조항은 유료 표준이라 원문 확인 못 함.
- 지연(B)·복합(D)의 세부 단계는 **외부 안전기준이 아니라 이 프로젝트 자체 실측 데이터 분석 결과**임을 발표/보고 시 명확히 구분해서 설명해야 함 (예: "KOSHA가 이렇게 정했다"가 아니라 "우리 데이터를 분석해보니 이렇게 나뉘었고, 거기에 공식 안전 원칙을 결합했다").
