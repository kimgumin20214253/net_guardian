# 프로젝트 구동 방법 (2026-09-04 기준, 4-class 시나리오 분류 파이프라인)

> 정식 파이프라인은 **4대 시나리오(Normal/Delay/Loss/Combined) 분류**입니다.
> 입력 피처는 `rtt`, `loss_flag`, `jitter` 3개, 라벨은 0(정상)/1(지연)/2(유실)/3(복합)입니다.

## 전체 구조
```
net_guardian/
├── frontend/     # Next.js 대시보드 (팀원 작업)
└── backend/      # 이 문서가 다루는 부분 (Python: 학습/평가/실시간 수집/API 서버)
    ├── api/main.py               # 모델 서빙 FastAPI 서버
    ├── network/                   # Modbus 서버 + tc netem 자동 주입 스크립트
    ├── raw_dataset_20260904/      # 실측 완료된 4개 시나리오 원본 데이터
    ├── models/                    # train_and_benchmark.py 실행 후 생성됨
    ├── train_and_benchmark.py, evaluate.py, packet_analyzer.py
    └── requirements.txt
```
아래 명령어는 전부 **`backend/` 안에서** 실행한다고 가정합니다. 먼저 이동하세요:
```
cd backend
```

## 1. 기존 수집 데이터로 학습 + 평가 (가장 흔한 경로)
`raw_dataset_20260904/`에 이미 실측 데이터가 있으므로, 새로 수집하지 않아도 바로 학습/평가를 돌릴 수 있습니다. Windows/Linux 어디서나 동작하고, 스크립트 자체가 자기 파일 위치 기준으로 경로를 잡기 때문에 `backend/` 밖에서 실행해도 결과물은 항상 `backend/` 안에 정확히 저장됩니다.

```
python train_and_benchmark.py
```
- `benchmark_results.csv`: 4개 모델(Logistic Regression, Decision Tree, Random Forest, LightGBM) 벤치마크 결과
- `rf_feature_importance.png`: Random Forest 피처 중요도
- `models/rf_best_accuracy.pkl`, `models/dt_low_latency.pkl`: 저장된 최종 모델

```
python evaluate.py
```
- 콘솔에 Accuracy/Precision/Recall/F1(Macro) 출력
- `models/confusion_matrix.png`: 4x4 컨퓨전 매트릭스 생성

## 2. (선택) 신규 실시간 데이터 수집
Modbus 통신 장애를 실제로 주입하며 새 데이터를 쌓고 싶을 때만 필요합니다. `tc netem`은 Linux 전용이라 **Ubuntu 환경**에서 진행하는 것을 전제로 합니다 (`docs/환경구축.md` 참고).

**터미널 1 (Modbus 서버)**
```
python network/server.py
```

**터미널 2 (실시간 수집 엔진)**

⚠️ 아래 스크립트들은 `.current_label` 파일을 현재 작업 디렉터리(cwd) 기준으로 주고받으므로, **반드시 `backend/` 안에서** 실행해야 서로 같은 파일을 보게 됩니다.
```
python packet_analyzer.py
```
- 저장 위치: `data/net_guardian_scenario_dataset.csv` (최초 실행 시 자동 생성, 이후 이어쓰기)
- 컬럼: `timestamp, rtt, loss_flag, jitter, label`

**터미널 3 (장애 시나리오 자동 주입 + 라벨 갱신)**

`network/master_collector.sh`가 4개 시나리오(A/B/C/D)를 순환하며 `tc netem`으로 장애를 주입하고, 그때마다 `.current_label`에 `A`/`B`/`C`/`D`를 자동으로 기록합니다. `packet_analyzer.py`의 라벨 매핑(A=0,B=1,C=2,D=3)과 일치하므로 별도 수동 조작은 필요 없습니다.
```
bash network/master_collector.sh
```

**터미널 4 (로그 확인, 선택)**
```
tail -f data/net_guardian_scenario_dataset.csv
```

## 3. 모델 서빙 API 서버 (대시보드 연동용)
`models/rf_best_accuracy.pkl`을 로드해서 대시보드(Next.js)가 호출할 수 있도록 HTTP API로 열어줍니다.
```
venv\Scripts\python.exe -m uvicorn api.main:app --reload --port 8000
```
- `GET /health` — 서버/모델 상태 확인
- `POST /predict` — `{"rtt": 42.0, "loss_flag": 0, "jitter": 3.1}` 형태로 요청하면 4-class 예측 + 클래스별 확률 반환
- `GET /telemetry/latest?n=50` — 최근 데이터 N건 + 각 건의 예측 결과. `data/net_guardian_scenario_dataset.csv`(실시간 수집 결과)가 있으면 그걸 쓰고, 없으면 `raw_dataset_20260904/`에서 4개 시나리오를 섞은 데모용 샘플을 대신 반환 (응답의 `source` 필드로 `"live"`/`"demo"` 구분)
- 브라우저에서 `http://127.0.0.1:8000/docs` 접속하면 Swagger UI로 직접 테스트 가능
- Next.js 개발 서버(`localhost:3000`) 기준으로 CORS 허용되어 있음

## 4. 프론트엔드 대시보드 (frontend/)
```
cd ../frontend
npm install     # 최초 1회
npm run dev
```
`http://localhost:3000`에서 확인. API 서버(3번 섹션)가 `:8000`에서 함께 떠 있어야 실데이터 연동이 가능합니다 (현재는 아직 프론트 코드가 API를 호출하지 않고 더미 값을 표시 중).
