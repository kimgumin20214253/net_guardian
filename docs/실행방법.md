# 프로젝트 구동 방법 (2026-09-04 기준, 4-class 시나리오 분류 파이프라인)

> 정식 파이프라인은 **4대 시나리오(Normal/Delay/Loss/Combined) 분류**입니다.
> 입력 피처는 `rtt`, `loss_flag`, `jitter` 3개, 라벨은 0(정상)/1(지연)/2(유실)/3(복합)입니다.
> 대시보드(`gui/`)는 팀원이 별도 작업 중이라 이 문서에서는 다루지 않습니다.

## 현재 파일 구조 (핵심만)
```
train_and_benchmark.py     # 데이터 로드 + 4-class 학습/벤치마크 + 모델 저장
evaluate.py                 # 저장된 모델 재검증 + 4x4 컨퓨전 매트릭스 생성
packet_analyzer.py           # 실시간 Modbus RTT/손실/지터 수집 엔진 (레포 루트에서 실행)
requirements.txt

network/
├── server.py                # Modbus TCP 서버 (가상 PLC 역할)
└── master_collector.sh      # tc netem 장애 자동 주입 스크립트 (Linux 전용, ⚠️ 아래 주의사항 참고)

raw_dataset_20260904/        # 실측 완료된 4개 시나리오 원본 데이터
├── scenario_A_raw.csv       # 정상
├── scenario_B_raw.csv       # 지연
├── scenario_C_raw.csv       # 유실
└── scenario_D_raw.csv       # 복합

models/                      # train_and_benchmark.py 실행 후 생성됨
├── rf_best_accuracy.pkl     # Random Forest (Macro F1 최우수)
└── dt_low_latency.pkl       # Decision Tree (단건 추론 최저지연)
```

## 1. 기존 수집 데이터로 학습 + 평가 (가장 흔한 경로)
`raw_dataset_20260904/`에 이미 실측 데이터가 있으므로, 새로 수집하지 않아도 바로 학습/평가를 돌릴 수 있습니다. Windows/Linux 어디서나 동작합니다.

```
python train_and_benchmark.py
```
- `benchmark_results.csv`: 4개 모델(Logistic Regression, Decision Tree, Random Forest, LightGBM) 벤치마크 결과
- `rf_feature_importance.png`: Random Forest 피처 중요도
- `models/rf_best_accuracy.pkl`, `models/dt_low_latency.pkl`: 저장된 최종 모델

```
python evaluate.py
```
- 콘솔에 Accuracy/Precision/Recall/F1(Macro) 출력
- `models/confusion_matrix.png`: 4x4 컨퓨전 매트릭스 생성

## 2. (선택) 신규 실시간 데이터 수집
Modbus 통신 장애를 실제로 주입하며 새 데이터를 쌓고 싶을 때만 필요합니다. `tc netem`은 Linux 전용이라 **Ubuntu 환경**에서 진행하는 것을 전제로 합니다 (`docs/환경구축.md` 참고).

**터미널 1 (Modbus 서버)**
```
python network/server.py
```

**터미널 2 (실시간 수집 엔진)**
```
python packet_analyzer.py
```
- 저장 위치: `data/net_guardian_scenario_dataset.csv` (최초 실행 시 자동 생성, 이후 이어쓰기)
- 컬럼: `timestamp, rtt, loss_flag, jitter, label`

**터미널 3 (장애 시나리오 자동 주입 + 라벨 갱신)**

`network/master_collector.sh`가 4개 시나리오(A/B/C/D)를 순환하며 `tc netem`으로 장애를 주입하고, 그때마다 `.current_label`에 `A`/`B`/`C`/`D`를 자동으로 기록합니다. `packet_analyzer.py`의 라벨 매핑(A=0,B=1,C=2,D=3)과 일치하므로 별도 수동 조작은 필요 없습니다.

⚠️ **레포 루트에서 실행하세요** (`network/` 안에서 실행하면 `.current_label`이 다른 위치에 생겨 `packet_analyzer.py`가 못 찾습니다):
```
bash network/master_collector.sh
```

**터미널 4 (로그 확인, 선택)**
```
tail -f data/net_guardian_scenario_dataset.csv
```
